# Fluksos Technical Manual

Welcome to the Fluksos technical documentation. This folder is intended for developers, Tech Leads, and Maintainers who want to understand the deep technical decisions behind the scaffolds generated by the CLI.

If you are just looking for how to use the CLI, please check the [Main README](../README.md).

## Table of Contents

### 1. Architecture & Ecosystem
- 🏗️ **[Next.js Stack & Tiers](./NEXTJS_STACK.md)**: Understand the difference between Tier 1, Tier 2, and Tier 3. Deep dive into the Monorepo structure, Docker environments, and the full Observability Stack (OpenTelemetry, Grafana Faro, Loki, Tempo).
- 🤖 **AEO (AI Engine Optimization)**: *Documented within the Next.js Stack*. Learn how Fluksos natively supports LLMs and crawler agents.

### 2. Security & Boundaries
- 🔒 **[Security & Rate Limiting](./SECURITY.md)**: Understand our Zero-Day approach to security. Covers our implementation of Upstash Redis rate limiting, strict Content-Security-Policy (CSP), and Better Auth integration.

### 3. CLI Tooling & Automation
- ⚖️ **[The AST Tribunal (Validators)](./VALIDATORS.md)**: The heart of our governance. Learn how the internal AST Parser works to block structural crimes (like fetching inside a Client Component) before they can even be committed to the repository.
- ⚡ **[Code Generators](./GENERATORS.md)**: How to use `fluksos generate` to safely create Next.js Server Actions wrapped in Valibot validation, and Hono RPC Hooks for the client.

### 4. Contributing
- 🧑‍💻 **[Contributing Guide](./CONTRIBUTING.md)**: Want to add a new stack (e.g. NestJS) or fix a bug in the AST parser? Start here.
- 🤖 **[AGENTS.md](../AGENTS.md)**: The ultimate system prompt and repository rulebook for AI Coding Assistants working on the Fluksos engine.
